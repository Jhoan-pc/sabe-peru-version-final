## 1. Executive Summary & Problem Scope

This blueprint maps the technical debt, interface contracts, DOM architecture, and migration path required to harden the customer reservation system across `index.html`, `experiencia.html`, `src/reservations.ts`, `src/main.ts`, `src/experiencia.ts`, and `src/style.css`.

### Current State Flaws Identified:
1. **[DT-11] Asynchronous `window.open` Popup Blocking:** Both `src/main.ts` (line 810) and `src/experiencia.ts` (line 192) invoke `window.open(waUrl, '_blank')` immediately following an asynchronous network call (`await addDoc(...)`). In modern mobile browsers (iOS Safari, Android Chrome), any async delay strips user-gesture activation, resulting in silent popup suppression.
2. **Missing Collision-Resistant Locator (`SP-XXXX`):** Firestore insertions currently write un-indexed records without the mandatory booking code specified in `PROJECT.md` Interface Contract #3 (`^SP-[A-Z0-9]{4}$`).
3. **Absence of Atomic Pre-Flight Capacity Validation:** Slot capacity is only queried when the date `<input>` triggers a `change` event. At submission time, no re-validation occurs, allowing race conditions and overbooking beyond the strict 4-table limit (`MAX_ACTIVE_RESERVATIONS_PER_SLOT = 4`).
4. **Missing Group > 6 Pax Reaction:** Neither form reacts dynamically when a customer enters > 6 guests, violating Domain Rule §3.2.2 (Imperial Table Advisory requirement).
5. **Code Duplication & Lack of Type Safety:** The submission logic is duplicated between `src/main.ts` and `src/experiencia.ts`. Neither file uses domain interfaces; raw `FormData` queries and implicit `any` types exist.
6. **Incomplete Error Handling:** Errors are displayed as crude innerHTML text rather than structured RFC 9457 Problem Details floating toasts.

## 3. Code Inspection & Technical Debt Analysis

### 3.1. Active `window.open` Locations (DT-11)
- `src/main.ts`:
  ```typescript
  // Line 810:
  const newWindow = window.open(waUrl, '_blank');
  ```
- `src/experiencia.ts`:
  ```typescript
  // Line 192:
  window.open(waUrl, '_blank');
  ```
**Remediation:** Completely eliminate `window.open` from both files. Replace with rendering the `#reservation-confirmation-card` containing an accessible, voluntary anchor:
`<a id="btn-whatsapp-confirm" href="${waUrl}" target="_blank" rel="noopener noreferrer" class="btn-wa-confirm"><span>Abrir WhatsApp con Maître</span></a>`.

### 3.2. Native `alert()` Calls
- Current audit across `src/reservations.ts`, `src/main.ts`, and `src/experiencia.ts` confirms **0 occurrences of native `alert()`**.
- However, existing error recovery in `main.ts` and `experiencia.ts` relies on inline DOM message strings (`formMessage.textContent = 'Hubo un error...'`).
- **Remediation:** Centralize error handling using the project's standard RFC 9457 Problem Details engine (`showProblemToast`), raising structured toasts for:
  - `https://api.sabeaperu.es/errors/slot-full` (Status 422: Slot reached 4 active bookings).
  - `https://api.sabeaperu.es/errors/validation-error` (Status 400: Invalid pax or date).
  - `https://api.sabeaperu.es/errors/reservation-failure` (Status 500: Database network failure).

### 3.3. Capacity Checking & Firestore Logic
In `src/reservations.ts`:
```typescript
const q = query(
    collection(db, 'reservations'),
    where('reservation_date', '==', dateStr),
    where('status', '!=', 'cancelled')
);
const qs = await getDocs(q);
```
- Active bookings are correctly filtered (`status != 'cancelled'`).
- The 4-table threshold `(counts[time] || 0) < 4` is compliant with Domain Rule §3.2.1.
- **Flaw:** Only executed when the user selects a date. If time elapses before submit, slot exhaustion is not checked.
- **Remediation:** Implement `checkSlotAvailabilityAtSubmit(dateStr, timeStr)` within the submit pipeline. If `activeCount >= 4`, reject the submission with an RFC 9457 Problem Details error before touching Firestore.

## 5. Domain Engine Architecture (`src/reservations.ts`)

`src/reservations.ts` should be expanded to become the Single Source of Truth (SSOT) for all reservation domain math and UI orchestration:

### 5.1. Pure Domain Functions
```typescript
export const KITCHEN_HOURS: Readonly<Record<number, KitchenHours>> = Object.freeze({
  0: { open: '12:00', last: '21:30' }, // Domingo
  1: { open: '12:00', last: '23:30' }, // Lunes
  2: { open: '12:00', last: '23:30' }, // Martes
  3: { open: '12:00', last: '23:30' }, // Miércoles
  4: { open: '12:00', last: '23:30' }, // Jueves
  5: { open: '12:00', last: '23:30' }, // Viernes
  6: { open: '12:00', last: '22:30' }  // Sábado
});

export const MAX_ACTIVE_RESERVATIONS_PER_SLOT = 4;
export const MAX_STANDARD_GROUP_SIZE = 6;
export const MAX_TOTAL_GUEST_CAPACITY = 20;
export const LOCATOR_REGEX = /^SP-[A-Z0-9]{4}$/;

export function generateDaySlots(dayOfWeek: number): string[] {
  const hours = KITCHEN_HOURS[dayOfWeek];
  if (!hours) return [];
  const slots: string[] = [];
  let current = hours.open;
  while (current <= hours.last) {
    slots.push(current);
    const [h, m] = current.split(':').map(Number);
    const nextM = m + 30;
    const nextH = h + Math.floor(nextM / 60);
    const nextMFinal = nextM % 60;
    current = `${String(nextH).padStart(2, '0')}:${String(nextMFinal).padStart(2, '0')}`;
  }
  return slots;
}

export function checkSlotAvailability(activeCount: number): SlotCapacityResult {
  const isAvailable = (activeCount || 0) < MAX_ACTIVE_RESERVATIONS_PER_SLOT;
  return {
    available: isAvailable,
    reason: isAvailable ? undefined : 'Completo',
    activeCount
  };
}

export function validateGuestCount(people: number): GuestValidationResult {
  if (typeof people !== 'number' || !Number.isInteger(people) || people < 1 || people > MAX_TOTAL_GUEST_CAPACITY) {
    return {
      valid: false,
      isImperial: false,
      error: `Number of guests must be an integer between 1 and ${MAX_TOTAL_GUEST_CAPACITY}`
    };
  }
  const isImperial = people > MAX_STANDARD_GROUP_SIZE;
  return {
    valid: true,
    isImperial,
    notice: isImperial
      ? 'Grupos de más de 6 comensales requieren confirmación de mesa imperial con el maître.'
      : undefined
  };
}

export function generateReservationLocator(rng: () => number = Math.random): string {
  const alphabet = 'ABCDEFGHJKLMNPQRSTUVWXYZ23456789'; // 32 unambiguous chars (no 0/O, 1/I)
  let code = '';
  for (let i = 0; i < 4; i++) {
    const idx = Math.floor(rng() * alphabet.length);
    code += alphabet[idx];
  }
  return `SP-${code}`;
}

export function buildWhatsAppReservationUrl(params: WhatsAppReservationParams): string {
  const cleanPhone = (params.phone || '34662125650').replace(/\D/g, '');
  const message = `Hola, confirmo mi solicitud de reserva en Sabe a Perú con localizador ${params.locator} a nombre de ${params.name} para el ${params.date} a las ${params.time} (${params.people} personas).`;
  return `https://wa.me/${cleanPhone}?text=${encodeURIComponent(message)}`;
}
```

## 6. Dynamic UI Reaction for Groups > 6 (`#imperial-table-notice`)

When the customer modifies the number of people:
1. An event listener on `input[name="people"]` listens for both `'input'` and `'change'`.
2. It parses the numeric value: `const pax = parseInt(peopleInput.value, 10);`.
3. If `pax > 6`:
   - Sets `#imperial-table-notice` style to `display: flex`.
   - Populates warning copy:
     *"Grupos de más de 6 comensales requieren confirmación de mesa imperial con el maître."*
   - Adds `.visible` class for CSS transition.
4. If `pax <= 6`:
   - Sets `#imperial-table-notice` style to `display: none`.
   - Removes `.visible` class.
5. In addition, when the confirmation card is rendered, it includes `<div class="imperial-notice">...</div>` matching Tier 3 test assertion T3.4.5.
